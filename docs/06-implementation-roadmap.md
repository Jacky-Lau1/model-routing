# 06｜未来实施路线图

实施时严格按阶段推进；上一阶段未通过，不能开始下一阶段。

## Phase 0：兼容性实验室

目标：选择一个候选网关和一个候选执行模型，验证协议、工具闭环、身份日志与基线成本。产物：模型目录、测试夹具、10 次验证记录、Sol 基线。退出：满足 `docs/05` 的最低门槛。

## Phase 1：人工触发的单执行者闭环

目标：只允许操作者明确触发一个低风险任务，任务包 → 执行 → 本地测试 → Sol 审查。无自动选路。退出：范围、审计、失败关闭和恢复流程被真实验证。

## Phase 2：确定性控制层

目标：实现状态机、策略读取、任务包校验、运行报告、成本记录和强制升级；仍保持白名单任务类型。退出：重启后能从状态恢复，异常无静默降级。

## Phase 3：受限自动路由

目标：由规则自动判定低风险任务是否委派。实现每日/每版本回归基准，限制并发、预算和重试。退出：连续稳定的质量、成本和事故指标达到决策中冻结的阈值。

## Phase 4：维护与扩展

目标：模型轮换、策略版本化、回归告警、定期再认证和安全审计。每次上游 API、Codex 版本或模型版本改变，都重新执行相关验证。

## 实施前必答问题

1. 候选国内模型及其可接受的数据范围是什么？
2. API/网关的真实 OpenAI Responses 兼容程度和日志能力是什么？
3. 执行发生在哪台机器、以什么权限运行？
4. 基准项目和验收命令是什么？
5. Sol 升级的预算上限、人工审批点和停止条件是什么？
