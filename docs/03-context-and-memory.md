# 03｜上下文、记忆与兼容

不同模型的上下文窗口、工具调用格式、系统提示词处理和最大输出长度不同。兼容的目标不是让它们共享完整聊天记录，而是让每个阶段收到足以完成职责的结构化信息。

## 任务包

执行者只接收下列字段：目标、独立 read/write scope、禁止项、相关代码摘要/接口、验收要求、预算、停止条件、数据分类、外发授权、当前任务 ID 与最小背景摘要。S1 规范见 [数据合同说明](18-s1-data-contracts.md)、[TaskPackage schema](../config/task-package.schema.json) 和 [合成示例](../examples/task-package.example.json)。

不传递：完整高层推理、无关历史、密钥、原始用户敏感信息、未验证的中间猜测。

## 上下文预算

- 对每个候选模型维护真实的 `context_window`、`max_output_tokens`、工具支持和已验证日期；见 [model-catalog.example.yaml](../config/model-catalog.example.yaml)。
- 任务包的输入预算取候选模型最小可用窗口的保守比例（建议不超过 35%，并为工具输出与修复预留空间）。
- 达到阈值时由 Sol 生成结构化摘要；摘要必须列出不变量、已改文件、未解决问题、测试结果和下一步，不能只做散文式压缩。
- 任何模型窗口或 API 限制变更后，模型状态回退到 `unqualified`，重新测试。

## 持久记忆

未来每个项目都以版本化状态文件作为记忆真相源。聊天只是交互界面；状态文件才是可恢复的事实记录。恢复任务时，先读状态、任务包、验收结果和最新决策，再开始新的模型调用。

当前实现默认使用 ephemeral Codex 会话，并令普通事件只在内存中流转。只在审批、验证、审查、完成或阻塞边界原子更新 `.router-state`；DeepSeek 工具回合所需的 `reasoning_content` 不写入检查点。状态默认保留 7 天。

## 降低幻觉的机制

将“模型记住全部项目”替换为：范围白名单、明确接口、只读证据、可运行验证命令、diff 审查和失败升级。无法从代码或任务包证实的假设，必须标成待确认，而不能直接编码。
