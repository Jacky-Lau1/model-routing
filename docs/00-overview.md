# 00｜总体方案

## 要解决的问题

GPT-5.6 Sol 适合高不确定性工作：澄清需求、系统设计、跨文件取舍、故障归因与最终审查；但对每个小改动重复调用会消耗高价输入与输出 token。国内/低成本模型可承担界限明确、可测试的编码回合，但不能因为便宜就成为无约束的主控。

本方案用“规划—执行—验证—审查”的闭环降低成本，而不是用“模型换得更便宜”代替工程控制。

## 非目标

- 本阶段不安装任何路由器、插件或 SDK；
- 不配置真实 API Key；
- 不承诺任意国内模型都和 Codex 完全兼容；
- 不追求无人工监督的通用自治；
- 不以一次 benchmark 代替长期质量证明。

## 角色

| 角色 | 默认承担者 | 允许做什么 | 禁止做什么 |
| --- | --- | --- | --- |
| 协调者/规划者 | GPT-5.6 Sol | 澄清、架构、拆解、风险判断、验收 | 静默把关键工作交给未验证执行者 |
| 执行者 | 已验证的低成本模型 | 按任务包改代码、运行指定本地检查、报告差异 | 改范围、改架构、接触密钥、发布 |
| 确定性控制层 | 未来的 skill/plugin + 外部桥接 | 读写状态、选路、生成任务包、审计、失败关闭 | 根据模型自述伪造路由成功 |
| 质量门 | 本地工具 + Sol | lint/test/typecheck、差异审查、升级判定 | 在失败时放行 |

## 核心原则

1. **计划与执行分离**：低成本模型接收的是冻结的、最小化的任务包。
2. **失败关闭**：路由、身份、权限、测试任一不能证明，即停止或升级。
3. **证据优先**：日志、测试、diff 与版本化规则胜过提示词宣称。
4. **上下文是产物，不是聊天搬运**：跨模型只传摘要、约束、接口和验收标准。
5. **逐级放权**：先人工触发，再受限自动化；质量门不能跳过。
