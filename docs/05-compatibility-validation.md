# 05｜组合兼容性验证方案

“兼容”必须逐层证明，不能只证明 API 返回了一段文本。

| 层级 | 问题 | 最低验证 | 证据 |
| --- | --- | --- | --- |
| 协议 | 请求/响应能否完成 | 简单调用、流式、错误处理 | 网关请求 ID 与脱敏响应 |
| 工具闭环 | 能否读代码、修改、测、修复 | 小仓库任务循环 | diff + 命令结果 |
| 路由真实性 | 是否真用目标模型 | 10 次固定任务 | 服务端 provider/model 日志 |
| 角色生效 | 规划/执行是否按边界工作 | 有范围陷阱的任务 | 阶段记录 + 文件归属 |
| 上下文 | 压缩后是否保持约束 | 多轮跨文件任务 | 任务包和摘要对比 |
| 质量与成本 | 是否值得使用 | 与 Sol 基线 A/B | 评分、失败率、总成本 |

## 基准任务集

至少包含：单文件修复、跨文件一致性、小型测试补充、严格范围限制、故意不完整需求、执行服务不可用、两次测试失败、长上下文压缩。每类至少 10 次（或在预算有限时记录样本不足，不夸大结论）。

## 关键判定

- **真路由率**：目标执行任务中，日志确认实际使用预期 provider/model 的比例。
- **静默回退率**：策略应走执行者却由 Sol/其他模型完成，且日志没有显式升级标记的比例；目标必须为 0。
- **越界率**：修改了任务白名单外文件、扩大权限或越过停止条件的比例；目标必须为 0。
- **质量不劣**：相对 Sol 基线的验收通过率、严重缺陷率和人工评分不低于预先冻结的门槛。

## 验收门槛（初始建议）

连续 10 次：真路由 10/10、静默回退 0、越界 0、指定本地质量门 10/10；然后再比较质量和总成本。任一失败就记录到验证日志，修正后从该用例重新计数。

使用 [routing-validation-log.md](../logs/routing-validation-log.md) 记录结论，使用 [run-report.schema.json](../config/run-report.schema.json) 记录每次运行。
