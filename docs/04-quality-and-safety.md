# 04｜质量、安全与成本边界

## 质量门顺序

1. 控制层验证任务包完整性和文件范围；
2. 执行者产生最小 diff 与结构化运行报告；
3. 本地运行格式化、lint、类型检查、单元/集成测试（由任务包指定）；
4. Sol 审查 diff、测试证据、边界和架构一致性；
5. 归档结果与路由/成本证据。

任何一个门失败，都不允许标记完成。

## 权限与数据

执行者默认无发布权限、无生产凭据、无写入策略配置权限。真实 API Key 只注入到调用网关的最小进程；日志中仅保存密钥引用名或哈希，不保存值。公共仓库只能存脱敏模板与聚合指标。

## 成本定义

节省定义为：在同一基准任务集、同一验收标准下，`Sol 全程基线成本 - 分层方案总成本`。总成本包含规划、执行、重试、审查与失败回退，不能只比较执行模型单价。

Sol 的重复访问会消耗额度；缓存命中通常能降低一部分重复输入成本，但依赖精确前缀、足够长的重复内容与具体产品计费规则。缓存不是路由成功或零成本的保证。

## 允许自动化的质量阈值

在固定基准集连续至少 10 次运行中：真路由率 100%、零静默回退、零越权改动、质量门通过率达到预设目标，且人工审查未发现严重缺陷，才可扩大自动化范围。阈值由未来决策记录冻结，不在实现中临时放宽。
