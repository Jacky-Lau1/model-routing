# 02｜路由策略与状态机

## 状态机

`INTAKE → PLAN → EXECUTOR_REQUIRED → LOCAL_VALIDATE → REVIEW → COMPLETED`

异常分支：`PLAN/EXECUTOR_REQUIRED/LOCAL_VALIDATE/REVIEW → SOL_ESCALATION`；不能安全恢复时进入 `BLOCKED`。每一次转移都须写入运行报告。

| 阶段 | 责任者 | 退出条件 |
| --- | --- | --- |
| INTAKE | Sol | 目标、范围、仓库、风险等级已明确 |
| PLAN | Sol | 任务拆成可独立验收的小包 |
| EXECUTOR_REQUIRED | 控制层 + 执行者 | 路由身份可证明，改动在允许范围内 |
| LOCAL_VALIDATE | 本地工具 | 指定检查全部通过 |
| REVIEW | Sol | diff、测试、约束与风险均被审查 |
| COMPLETED | 控制层 | 结果、成本和日志已归档 |

## 可路由条件

仅当所有条件为真时，任务才可交给执行者：

- 任务是可局部化的实现、重构、测试补充或明确 bug 修复；
- 架构、公开接口、数据库迁移、权限和依赖升级不在本次范围内；
- 任务包有文件白名单、不可变约束、验收命令和停止条件；
- 候选模型处于“qualified”状态，且当前 API/网关验证未过期；
- 无密钥、生产环境、外部发布或敏感代码暴露需求；
- 执行预算和最大重试次数未超限。

## 强制升级条件

任何一项出现均交回 Sol：需求含糊；跨模块设计；安全/支付/认证；迁移或不可逆变更；测试失败两次；执行者越界；模型身份或调用日志缺失；上下文压缩可能遗漏关键约束；成本超预算。

## 失败关闭规则

1. 请求失败、超时或模型名不匹配：标记失败，保留证据，不换模型重试。
2. 只有用户/策略明确允许时，才能将任务升级回 Sol；运行报告必须注明原因。
3. 禁止“低成本模型失败后由 Sol 悄悄完成全部实现”而不在日志标记。Sol 可接管，但这是一条显式升级路径。
4. 模型自述、响应文本和 UI 标签不构成模型身份凭据；以网关/服务端记录为准。

策略示例在 [config/routing-policy.example.yaml](../config/routing-policy.example.yaml)。实际配置必须放在本机受保护路径，不能把密钥或本地端点写进公开仓库。
