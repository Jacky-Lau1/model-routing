# 07｜运行与维护手册

## 每次实现任务

1. 读取最新决策、模型状态和未关闭事件；
2. 创建任务包并冻结范围；
3. 选择已认证模型或显式升级；
4. 运行、保存脱敏运行报告和测试结果；
5. 更新验证/成本记录；
6. 若策略、模型或事实改变，更新决策与变更日志。

## 每周/每次升级

- 检查 Codex、网关和候选模型版本/协议是否改变；
- 对每个 `qualified` 模型运行最小回归；
- 审阅失败关闭、静默回退和越界计数；
- 检查日志脱敏与密钥轮换状态；
- 更新 `CHANGELOG.md` 和 `logs/decision-log.md`。

## 模型生命周期

`unqualified → testing → qualified → quarantined / deprecated`

只有记录了版本、网关、测试集和有效期的模型才可为 `qualified`。API 变更、严重异常、身份日志缺失或质量回归会立即进入 `quarantined`。

## 事件处理

触发条件包括：真实模型与预期不符、发生静默回退、越权文件变更、敏感数据进入外部请求、质量门错误放行、成本异常。立刻停止自动路由，轮换凭据（若涉及），保存脱敏证据，按 [事件模板](../logs/incident-log-template.md) 记录，修复后重新认证。
