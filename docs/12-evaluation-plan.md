# 混合模型路由测评方案（暂不执行）

## 目标与对照组

首轮采用可控的小样本 Pilot-30：6 个任务、5 套配置、每项 1 次，共 30 次运行。全部通过后再把每项重复 3 次，用于估计稳定性。五套配置为：全程 Sol、全程 Terra、全程 DeepSeek Flash、当前 Auto 路由、Auto 路由但复杂执行强制 DeepSeek Pro。每个配置使用相同任务、工具、文件范围、超时和最大输出预算，运行顺序随机化。

六个任务包括 3 个密封代码任务（TypeScript 局部修复、跨文件重构、测试失败诊断）、2 个纯文本任务（技术方案、冲突需求归并）和 1 个视觉任务（截图约束转为 UI 修改与截图验收）。首轮不使用真实私有仓库，也不把隐藏测试、参考答案或供应商密钥放进模型上下文。

## 执行框架

- 代码和终端任务使用固定提交版本的 Harbor，在 Docker 临时环境中运行自建任务。先用 Oracle 验证任务和评分器，再接入路由器适配器。
- 纯文本任务使用固定版本 Promptfoo 生成配置矩阵，但调用仍经过本路由器，以免绕过推理预算、敏感分级和成本记录。
- SWE-bench Verified 仅作为第二阶段外部效度检查，首轮最多选择 2 个经人工审计的实例；不直接下载并运行任意社区任务。
- 视觉任务使用本地合成截图和确定性 DOM/像素约束，不上传真实业务截图。

## 安全边界

1. 固定 Harbor、Promptfoo、任务仓库提交 SHA，并固定容器镜像 digest；依赖更新必须重新审计。
2. 人工检查每个 Dockerfile、测试脚本、安装脚本和参考解，拒绝特权容器、Docker socket、宿主目录写挂载和未知二进制。
3. 任务容器以非 root、只读根文件系统运行，限制 CPU、内存、进程数、磁盘和墙钟时间；每次运行后销毁。
4. 模型请求由宿主路由器发出。任务容器默认无外网，不接收 API Key；如必须联网，仅通过显式域名白名单代理。
5. 宿主只导出 verifier 结果、diff 摘要和去标识化指标。原始 reasoning 内容、完整对话和 API Key 不持久化。
6. 禁止浏览器、GitHub 登录态、SSH agent、云凭据、个人目录和真实源码进入测评环境。

## 指标

质量主指标为程序化 verifier 得分、任务通过率和 pass@1；辅助指标为隐藏测试通过率、允许文件范围违规、回归测试、修复次数和人工盲审分。主结论不依赖单一 LLM-as-a-judge。

效率指标按阶段和模型记录：输入 token、缓存命中/未命中 token、输出 token、供应商报告的 reasoning token、累计上下文 token、单轮最大活动上下文、轮数、工具调用数、压缩次数、首 token 延迟、总耗时、重试和公开价格等价成本。供应商未报告 reasoning token 时记为 `N/A`，不从隐藏思维文本推算。

上下文长度同时报告三项：`max_active_context_tokens`、`cumulative_input_tokens` 和 `context_growth_tokens_per_turn`。这样可以区分“单轮上下文过长”和“多轮重复发送造成的累计浪费”。对话长度使用用户/助手/工具轮数与持久化字节数，不只看字符数。

## 通过门槛

- 路由身份命中率 100%，不得静默回退。
- 允许范围违规和敏感数据外发均为 0。
- Auto 相比全程 Sol 的质量下降不超过 2 个百分点。
- Auto 的公开价格等价成本至少降低 30%，中位耗时至少降低 15%。
- Auto 的累计输入 token 至少降低 20%，且 reasoning token 不因自动升级规则出现无上限增长。
- 任一配置出现越界写入、密钥暴露、容器逃逸迹象或预算失控，整批测评立即停止。

## 输出

最终生成一份版本化 JSONL 原始指标和一份 Markdown 报告。报告展示每配置的质量、成本、耗时、上下文、reasoning、缓存和失败类型，并附任务版本、模型请求 ID、路由决策与预算。公开 API 价格只标为“等价成本”；ChatGPT/Codex 登录额度不标为实际 API 账单。
